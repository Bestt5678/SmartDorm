ระบบจองห้องพักและจัดการหอพักออนไลน์ ที่รวมการค้นหาห้อง การจอง สัญญา ใบแจ้งหนี้ การชำระเงิน และงานซ่อมไว้ในที่เดียว

01 · Overview

ปัญหาและเป้าหมาย

ปัญหาที่พบ
  • การจองห้องและการติดต่อทำผ่านหลายช่องทาง
  • สถานะห้อง การจอง และการชำระเงินไม่รวมศูนย์
  • เอกสารสัญญาและใบแจ้งหนี้ต้องจัดทำซ้ำด้วยมือ
  • ผู้เช่าไม่สามารถติดตามสถานะได้ด้วยตนเอง
เป้าหมายของระบบ
  • ให้ผู้เช่าค้นหาและจองห้องได้ด้วยตนเอง
  • ให้ผู้ดูแลยืนยันการจองและออกเอกสารในระบบเดียว
  • ติดตามการชำระเงินและงานซ่อมได้แบบเรียลไทม์
  • ลดงานเอกสารซ้ำซ้อนและข้อผิดพลาดจากข้อมูลกระจัดกระจาย

02 · Scope

ขอบเขตของโปรเจกต์

อยู่ในขอบเขต
  • ค้นหา กรอง และดูรายละเอียดห้องพัก
  • สมัครสมาชิก เข้าสู่ระบบ และจัดการสิทธิ์ตาม role
  • ส่งคำขอจอง ติดตาม และยกเลิกการจอง
  • สัญญาเช่า ใบแจ้งหนี้ และการชำระเงินแบบ Mock
  • แจ้งซ่อมและติดตามสถานะงานซ่อม
  • หลังบ้านสำหรับ ADMIN และ STAFF
ยังไม่อยู่ในขอบเขต
  • เชื่อมต่อ payment gateway จริง
  • แจ้งเตือนผ่าน LINE หรือ Email
  • Mobile application
  • ยืนยันตัวตนด้วย OTP หรือ e-KYC
  • ระบบแชทระหว่างผู้เช่าและผู้ดูแล
  • รายงานวิเคราะห์เชิงลึกขั้นสูง

03 · Users

บทบาทและสิทธิ์การใช้งาน

05 · Data Model

โครงสร้างฐานข้อมูล

ตารางหลัก
room_type room tenant booking contract invoice payment
ตารางสนับสนุน
staff utility_meter repair_request account
ความสัมพันธ์สำคัญ
  • room_type 1:N room
  • tenant 1:N booking
  • booking 1:1 contract
  • contract 1:N invoice
  • invoice 1:N payment
  • room 1:N meter / repair

เพิ่ม partial unique index เพื่อป้องกันห้องถูกจองซ้ำขณะมี booking ที่ยัง active

08 · Security

ความปลอดภัยและการออกแบบ API

Authentication & Authorization
  • รหัสผ่านถูก hash ด้วย bcrypt
  • ออก token ด้วย JWT และกำหนดวันหมดอายุ
  • ตรวจสอบ role ใน middleware ก่อนเข้าถึง endpoint
  • ผู้เช่าเข้าถึงได้เฉพาะข้อมูลของตนเอง
Validation & Hardening
  • ตรวจ payload และ query ด้วย Zod ทุก endpoint สำคัญ
  • ใช้ helmet, CORS และ rate limit
  • ไม่ commit ไฟล์ .env หรือ secret ลง repository
  • แยกชั้น routes, services และ data access
